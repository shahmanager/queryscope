# QueryScope Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build QueryScope — a zero-API-cost, retrieval + typed-compiler NL-to-SQL tool with measured evaluation and a consulting-style business case.

**Architecture:** A deterministic compiler backbone (schema introspection → composable intent family → typed logical plan → validation → parameterized SQL → read-only execution) with an interchangeable retrieval front-end (stdlib lexical default, optional local semantic). A benchmark harness generates all reported numbers; an ROI calculator and README turn it into a consulting artifact.

**Tech Stack:** Python 3.10+, stdlib sqlite3/http.server, pytest, optional sentence-transformers.

**Spec:** `docs/superpowers/specs/2026-11-22-nl2sql-design.md`

## Global Constraints

- Python 3.10+; no API calls, no telemetry, no paid compute.
- Default install requires zero model downloads; semantic scorer is opt-in via `pip install -e ".[semantic]"`.
- SQLite via stdlib; all values parameterized; identifiers only from introspected catalog.
- Read-only execution: `mode=ro` URI + `PRAGMA query_only=ON`.
- All README numbers generated by `scripts/run_eval.py`; never hand-written.
- `EVAL_NOW = 2026-06-30` pinned for evaluation.

## Review Focus

1. User text reaching SQL as an identifier or literal → structural allowlist + bound params; test in Task 5.
2. Relative time drifting between gold and actual → injectable clock; test in Task 4.
3. Threshold tuned and scored on the same data → split harness; test in Task 8.
4. Ambiguous question returning a guessed query → `needs_clarification` status; test in Task 4.
5. Refusals measured only on out-of-scope → precision across all categories; test in Task 8.
